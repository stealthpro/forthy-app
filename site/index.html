Built for the way Laravel
actually runs

No Composer package, no route to expose and no server to keep alive. The bridge is embedded in the app and boots your real application.

Tinker with structure

Run PHP in a warm session and read dumps as native trees: models, collections, arrays, exceptions. Every query arrives with bindings, the file that triggered it and timing.

Artisan, searchable

Find any command by name, pin favorites above the list and stream output into its own console tab. Aliases are deduplicated; history keeps the rest.

Models and relations

Open a model as a reference page: real columns, casts, relations, methods and scopes. Follow a relation to the next model without losing your place.

A database explorer

Browse tables with a typed filter builder, sort and page through rows, and inspect indexes and foreign keys. Export the current view to CSV or JSON.

Routes and config

Read the running route table — middleware, handlers, resolved URLs — and the real configuration tree, with secrets masked. The project's .env opens in a read-only modal where secret-looking values stay masked until you reveal them.

Logs that follow

Follow single, daily or custom log files. Levels and stack traces are parsed, traces collapse until you need them, and the view is always read-only.

Your application's files

Every filesystem disk from config/filesystems.php opens its own file-manager tab: preview images, CSV, Excel, Word and PDF in place, download a whole folder as an archive, upload with a destination-first dialog that marks each replacement before it happens, and delete a file or a folder after a counted confirmation while `.gitignore`-style placeholders stay locked. Nothing is indented into a tree, so a folder ten levels deep is one click away.

How it works

Three steps, no setup in your project

  1. 1

    Add a connection

    Pick a local folder, a Docker service, an SSH host or a Kubernetes pod. Forthy probes PHP and boots Laravel before it saves anything.

  2. 2

    Work with the real app

    Run PHP, inspect models and tables, search routes and config, stream Artisan and follow logs — all against the application as it runs now.

  3. 3

    Keep the useful bits

    Save snippets, keep run and Artisan history, pin favorites. All of it lives in a local SQLite database; nothing is uploaded anywhere.

Safety

Local-first by construction

Forthy is a desktop app, not a service. Your project stays where it is.

  • No package, route or server is installed in your application.
  • Connections, snippets and settings live in local SQLite.
  • SSH passwords stay in memory for the session — never on disk, in a log or in argv.
  • Destructive code is flagged before it runs; nothing runs on import.
  • Optional locks ask macOS — Touch ID or the Mac password — before the app or a chosen project opens. Forthy stores only a flag.
  • Database browsing and logs are read-only; no telemetry, no accounts.

FAQ

Questions, answered

Is Forthy free?

The macOS build is free to download and use. Forthy is proprietary software: redistribution and modification are not permitted. See the license.

Do I need to install anything in my Laravel project?

No. The PHP bridge is embedded in the app, copied into the target or streamed over stdin. There is no Composer package, no route and no server to deploy. For remote targets the app does need a POSIX shell and PHP in the container or host.

Which Laravel and PHP versions are supported?

Laravel 10 through 13, with PHP 8.1 or newer. Older Laravel 10.x releases are handled by schema fallbacks in the bridge.

Does it work on Intel Macs?

Not yet — the published build is Apple Silicon only (arm64). There is no separate Intel download.

How are SSH passwords handled?

A password is asked once, passed to ssh through a private askpass helper and kept in memory for the session. It is never written to the database, an export, a workspace or a log. Key and agent authentication are the default.

Is my code or data sent anywhere?

No. There is no telemetry and no account. Connections, snippets and settings stay on your Mac; remote execution happens only on the target you configure.
